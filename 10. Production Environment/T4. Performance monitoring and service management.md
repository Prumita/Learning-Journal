## Why is reliability a feature?
What does reliable mean? For IT folks, if lights are green and nothing has crashed then that's okay.
Users don't care about that though, they expect that to be running. So they care about:
- Is data fresh?
- Is it fast?
- Is it right?

Sales pipeline runs every night, green every morning. Issue upstream sends empty file.
Technically still green, 0 rows load no problem, no failure.
End user then gets a dashboard saying 0, so they're either unhappy or misinformed.
So that example, server is up, but for end users that has failed. Reliability is measured in outcomes therefore, not just, is it up?
Did it arrive? at the right time? In the right shape?
